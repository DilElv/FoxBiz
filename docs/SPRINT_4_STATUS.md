# Sprint 4 — Purchasing

Tanggal: 17 November 2026. Acuan: PRD, Technical Architecture & ERD, Design System dan Sprint Plan di `docs/`. Backend tetap NestJS/Node.js. Status: implementasi Sprint 4 dan seluruh quality gate lokal selesai/PASS. UAT dan deployment produksi terpisah.

## Implementasi dan baseline bisnis

- Supplier master tenant-shared: nama unik per tenant, kontak bebas maksimal 200 karakter, status aktif/nonaktif, pencarian dan pagination 25 data. Pengguna dengan `purchasing.suppliers.write` dapat mengelola supplier; perubahan tidak mengubah snapshot supplier pada PO lama.
- PO per outlet dengan nomor UUID prefiks `PO-` unik per tenant; snapshot supplier/nama/SKU/satuan, kuantitas hingga tiga desimal, biaya per unit hingga dua desimal. Total dihitung server dengan Decimal, pembulatan HALF_UP dua desimal per baris, lalu dijumlahkan. Biaya nol diperbolehkan; nilai melampaui Decimal(14,2) ditolak.
- Lifecycle `draft → ordered → partially_received → received`, dan `draft|ordered → cancelled` sebelum penerimaan pertama. Draft dapat diubah dengan pemeriksaan `version`; setelah dipesan supplier, item dan biaya dikunci. Pembatalan wajib alasan 3–200 karakter. Tidak ada approval berjenjang; izin pemesanan terpisah dari pembuatan draft.
- Penerimaan menggunakan jumlah aktual per item, boleh subset item/parsial dan harus positif. Produk duplikat, produk di luar PO, penerimaan berlebih, PO draft/selesai/batal ditolak. PO selesai ketika semua item terpenuhi. Tidak ada pembatalan sisa pesanan setelah penerimaan parsial dalam baseline ini.
- PO baru dan pemesanan hanya memakai supplier serta produk aktif. Supplier/produk yang dinonaktifkan setelah PO dipesan tetap dapat dipenuhi untuk komitmen PO lama. Outlet penerima tetap wajib aktif dan dapat diakses pengguna.
- `goods_receipts` terhubung satu-ke-satu dengan `stock_documents` jenis `receiving`, status `posted`; setiap item memakai `stock_movements` jenis `purchase_receipt`, snapshot saldo dan referensi `stock:<documentId>`. Ledger hanya ditulis sekali melalui helper transaksi StockService. Penerimaan manual Sprint 3 tetap independen. Rincian dokumen stok menampilkan nomor PO terkait.
- Satu transaksi mencakup receipt/items, dokumen stok/items, saldo, ledger, jumlah diterima per item, versi/status PO, dan audit. Advisory lock tenant/key, row lock PO, share lock outlet/produk, serta row lock saldo terurut mencegah posting ganda dan over-receipt bersamaan. Kegagalan membatalkan seluruh transaksi; saldo minimal nol dan tidak melampaui kapasitas Decimal.
- Idempotency PO dan receipt memakai namespace terpisah, UUID tenant-unique, hash payload ternormalisasi dan pembuat. Key+body+pembuat sama mengembalikan dokumen terdahulu; body/pembuat berbeda `409`. Lookup recovery dibatasi pembuat, tenant dan outlet. Pengiriman ulang PO tidak mengembalikan draft ke versi awal bila draft sudah diedit.
- Permission baru: `purchasing.read`, `purchasing.suppliers.write`, `purchasing.orders.write`, `purchasing.orders.order`, `purchasing.orders.cancel`, `purchasing.receive`. Owner mendapat seluruhnya, manager default mendapat seluruhnya, inventory default hanya baca/terima. Role khusus dan cashier dipertahankan. Foreign key memakai tenant untuk supplier/outlet/aktor/produk/PO/receipt/dokumen stok; receipt item juga dikunci ke PO yang sama.
- UI `/purchasing`: supplier CRUD, pencarian/pagination supplier dan produk, form PO multi-baris, edit draft, filter status, konfirmasi pesan/batal, penerimaan parsial dengan sisa per item, riwayat dan rincian receipt, serta tampilan berdasarkan permission. Berganti outlet melalui header/profil memuat ruang kerja outlet baru.
- Browser menyimpan payload/key immutable di `sessionStorage` sebelum membuat PO/receipt. Respons tidak pasti menyediakan pemeriksaan status dan kirim ulang key sama, termasuk setelah reload. Jika penyimpanan browser gagal, request tidak dikirim. Menutup panel tidak membatalkan dokumen server. Perubahan draft memakai versi optimistis; respons hilang pada edit memerlukan muat ulang PO untuk memeriksa hasil.

## Batas cakupan

Biaya pembelian dicatat di PO tanpa mengubah harga jual atau cost master produk, tanpa valuasi/COGS dan tanpa posting Finance/utang/pembayaran supplier. Pajak/diskon/ongkir PO belum dimodelkan. Belum ada approval berjenjang, retur pembelian, void/edit receipt posted, cetak PO/surat penerimaan, jatuh tempo, kurs, lampiran atau penutupan sisa parsial. Supplier dimiliki tenant dan dapat dibaca staf Purchasing yang ter-scope outlet; PO/receipt tetap dibatasi outlet. Nomor PO memakai UUID, bukan urutan bisnis harian.

UI memakai token Blue/White/teal, Inter, rounded cards, komponen aksesibel dan Foxi sumber. Tabel lebar memakai scroll horizontal di kartu. Tidak diklaim pixel-perfect terhadap seluruh mockup DOCX. Dashboard aktual tetap Sprint 8; dashboard sekarang data demo.
